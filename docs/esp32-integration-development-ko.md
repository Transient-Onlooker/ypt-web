# ESP32 연결 개발 상태

기기 연결 기능의 구현과 검증 범위를 기록한다. 운영 반영 여부는 배포 이력과 실제 환경을 확인한다.

기기 연동 Worker와 웹 설정 화면의 초안이 추가되었다. ESP32 설정·전송 시험 펌웨어가 별도로 준비되어 있다. 실제 계정과 기기 간의 전체 연결 시험은 아직 완료되지 않았다.

기기 연결 흐름의 개발 인터페이스:

1. 기기가 8자리 일회용 코드와 256비트 무작위 기기 토큰을 생성하고, 토큰의 SHA-256만 `/api/device/pair/begin`에 HTTPS로 제출한다. 서버는 코드의 SHA-256과 토큰 해시를 5분 보관한다.
2. 로그인한 사용자가 ypt-web 설정에서 코드를 제출해 해당 계정에 기기를 연결한다. 코드는 한번만 사용된다.
3. 기기는 `Authorization: Device <token>`으로 `/api/device/session`, `/api/snapshot`, `/api/timer/start`, `/api/timer/stop`, `/api/timer/resume`만 사용할 수 있다. 시작과 정지는 기존 revision, operationId 및 서버 상태 확인 로직을 그대로 사용한다.
4. 웹 설정의 기기 조회·연결 해제는 로그인 세션과 기존 CSRF 조건을 사용한다. 연결 해제 후 토큰은 바로 거절된다.

남은 요구사항: HTTPS 인증서 검증 및 갱신, 초기 AP 보호와 로컬 설정 화면 인증·CSRF, 기기 토큰 안전 저장과 재등록, 타이머 결과 불확실성, 화면·버튼 연결, 로컬 설정 및 AP 타임아웃, 한글 글꼴, 백라이트 안전검증, 네트워크 오류·재시작·권한 폐기 실기기 시험. 운영 D1 이관 시 devices 테이블 추가와 계정 정리 정책 변경을 함께 배포해야 하며, 배포 전 리뷰가 필요하다.

시험 환경의 Worker 모의 테스트에서 등록·코드 만료·중복 거부·접근 범위·시작/정지·연결 해제를 확인했다. 실제 열품타 계정, 실제 ESP32, 운영 환경은 테스트하지 않았다.
