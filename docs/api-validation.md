# 열품타 API 검증 기록

## 운영 주소 사용자 확인 — 2026-09-25

- 사용자가 `https://ypt.mcv.kr`에서 자신의 열품타 계정 로그인, 과목 타이머 시작·종료가 모두 성공했다고 보고했습니다. 이메일·비밀번호·JWT·과목명·정확한 공부시간은 수집하거나 기록하지 않았습니다.
- 별도로 자동 검사에서 GitHub Pages 배포 성공, 도메인 HTTPS 200, JS 자산 200, HTTP→HTTPS 리다이렉트, Worker의 Pages 출처 `/api/session` 200을 확인했습니다. 실제 계정 브라우저 조작은 사용자가 수행했으며 자동 검사 결과와 구분합니다.
- 브라우저의 비밀번호 저장 제안과 날짜별 기록·그룹 표시를 운영 주소에서 다시 확인한 결과는 아직 없습니다.
- 같은 사용자가 앱 화면의 타이머 표시가 때때로 느려졌다 빨라지는 반면 웹 화면에서는 그 지연을 보지 못했다고 추가로 보고했습니다. 이전에 관찰한 약 0.5초 차이를 웹의 고정 지연으로 단정하지 않습니다. 앱 화면 표시와 서버 기록의 추가 정량 비교는 수행하지 않았으며, 웹의 시계 보정값을 임의로 바꾸지 않았습니다.

## 출처와 구분

- 참고 구현: [deveworld/ypt_client `bf05d2d`](https://github.com/deveworld/ypt_client/tree/bf05d2d10626f996a7e8f3eb3e7e85eb26bfdd0e)의 `lib/ypt_api.dart`, `lib/models.dart`. 경로·필드명은 참고 구현을 출발점으로 삼았습니다.
- 기존 실제 계정 검증: `ypt-timer-bridge`의 `docs/ypt-api-validation.md`와 2026-09-23 비식별 `.ypt-local/api-probe.json`. 웹 시작/종료 2회, 10초 휴식 제외, 기록 증가 60.136초가 확인됐습니다.
- 이 저장소의 실제 계정 검증: 2026-09-24 비식별 `.ypt-local/discovery-1790259793428.json`, `.ypt-local/cross-stop-1790260152353.json`, `.ypt-local/reverse-1790262332221.json`, `.ypt-local/history-1790262465901.json`, `.ypt-local/groups-1790263042321.json`. 파일은 공개 저장소에 올리지 않습니다. JWT·비밀번호·프로필은 저장하지 않았습니다.

## 확인된 응답과 동작

| 항목 | 실제 검증 결과 | 적용 범위 |
| --- | --- | --- |
| 앱 타이머 조회 | `POST /user/v2/reload/info`의 `p.is`가 정지 시 `false`, 앱 실행 중 두 조회에서 `true`, 앱 종료 후 `false`. 실행 중 `p.st`는 시간대가 포함된 시각으로 두 번 동일했고 `p.sb`도 동일했습니다. | 상태·과목·정확한 시작 시각을 읽습니다. 시간대 없거나 값이 불일치하면 제어하지 않습니다. |
| 앱 시작 → 웹 종료 | 앱 실행 중 `p.st`의 밀리초 값을 그대로 `POST /study/stop`의 `startedAt`에 사용했습니다. HTTP 200·`s:true`, 이후 `p.is:false`. 오늘 총시간은 20,279ms 증가했습니다. 앱에도 정지 기록이 표시됐습니다. | 앱에서 시작한 타이머의 웹 종료 허용. 요청은 한 번만 전송. |
| 웹 시작 → 웹 종료 | 기존 검증에서 성공. 당시 웹 시작 직전 밀리초를 종료에 사용했습니다. 이후 웹 시작 성공 시 `reload/info`의 `p.st`를 재조회하는 방식으로 개선했습니다. | 시작 시각·과목이 재조회에서 확인될 때만 웹 시작을 확정하며, 그 시각을 일시정지·종료에 사용. 재조회가 불확실하면 자동 재시도 없이 복구 상태로 전환. |
| 웹 시작 → 앱 종료 | 2026-09-24 검증 통과. `POST /study/start`는 HTTP 200·`s:true`, 조회된 `p.is:true`와 과목·시작 시각을 확인했습니다. 앱에서 종료한 뒤 `p.is:false`, 총시간은 17,687ms 증가했습니다. API가 반환한 시작 시각과 웹 요청 직전 시각은 1,162ms 차이였습니다. | 앱에서 종료한 웹 타이머는 다음 상태 조회 때 종료 상태로 조정. |
| 오늘 기록 | `dl.dt`는 `2026-09-24`, `dl.sm`은 총 밀리초. 종료 후 `dl.ls`의 두 구간 `sm` 12,904 + 19,076 = 총 31,980ms. | 오늘 총시간과 과목별 구간 합계 표시. 진행 중에는 완료된 기록과 현재 타이머를 구분. |
| 가입 그룹·멤버 | 첫 인증 조회에서는 그룹이 0개였습니다. 가입 후 `GET /group/groups/v2`와 `GET /logs/group/members/v2` 모두 HTTP 200·`s:true`였습니다. 당시 그룹 1개, 멤버 4명, `im:true` 4명이고 `dl.sm` 합계는 9,097,846ms였습니다. 이후 앱에서는 아무도 공부 중이지 않은데 웹에서는 4명 모두 공부 중이라고 표시되어 `im`이 현재 공부 상태라는 해석이 반증됐습니다. 2026-09-25 실제 계정 재조회에서 쉬는 네 명 모두 `dl.is:false`였고, 사용자가 앱에서 타이머를 시작하자 본인 멤버만 `dl.is:true`로 바뀌었습니다. 그룹 `dl.st`와 본인 프로필 `p.st`는 같은 시각이었습니다. 실행 중 두 조회 사이 `dl.sm`은 134,028ms로 일정했고, 앱 정지 후 `dl.is:false`, 기록은 254,287ms로 늘었습니다. 사용자가 그룹 화면도 자동 갱신 후 앱 상태와 일치한다고 확인했습니다. `mc:50`은 현재 인원 4명이 아닌 정원입니다. | 가입 그룹·멤버 수, `dl.is` 상태, 완료 기록과 분리한 실시간 진행 시간 표시. 선택한 그룹은 화면이 보이는 동안 15초마다 갱신. |
| 과거 날짜 | 인증된 `GET /logs/day?date=2026-09-24`가 HTTP 200·`s:true`를 반환했습니다. `dl.dt`가 요청 날짜와 같고, `dl.sm` 69,946ms가 `dl.ls` 4개 구간 `sm`의 합과 같았습니다. 이전 비인증 호출은 HTTP 200이어도 `s:false`, `c:108`이었습니다. | 날짜 선택과 총시간·과목별 구간 합계 표시를 허용. 응답 날짜가 다르거나 필드가 없으면 표시하지 않음. |

앱의 공부 날짜는 API의 `dl.dt`를 그대로 사용합니다. 사용자의 휴대폰 시간대나 브라우저 날짜에서 역산하지 않습니다. 그룹 목록은 화면이 보이는 동안 30초마다, 선택한 그룹의 멤버는 기본 15초마다 요청하며 화면에서 타이머 상태·멤버 조회 주기를 변경할 수 있습니다. `p.is`와 `p.st`의 해석은 위 실제 계정 조회를 근거로 하고, 새 응답이 이 조건을 만족하지 않으면 결과를 미확인으로 처리합니다.

2026-09-25 사용자는 웹 진행 시간이 약 2초 빠르고, 웹 표시 42초에 종료했을 때 앱 기록은 약 40초라고 보고했습니다. 계정 정보 없는 요청에서 열품타 HTTP `Date` 헤더가 로컬 시계보다 약 2초 느린 것을 반복 확인했습니다. 웹 표시에는 응답 헤더의 초 단위 시각과 요청 왕복 시간을 이용한 오프셋을 적용했습니다. 종료 요청에 보내는 `p.st`는 변경하지 않습니다. 이 보정의 실제 계정 재검증은 남아 있습니다.

같은 날 실제 계정으로 앱과 웹 타이머를 다시 비교했을 때 사용자는 약 0.5초 차이를 보고했고, 원격 화면 조정 지연이 포함됐을 가능성도 언급했습니다. HTTP `Date`의 초 단위 정밀도와 관찰 환경 때문에 추가 고정 보정값은 적용하지 않았습니다.

참고 클라이언트는 과목의 `co`를 ARGB 색으로 읽습니다. 웹은 유효한 `co`/`c` 값이 있을 때 색점을 표시하며, 사용자가 실제 계정 화면에서 과목 색이 잘 불러와진다고 확인했습니다.

## 코드 변경 후 회귀 검증

모의 열품타 응답을 사용하는 통합 테스트에서 응답 유실 뒤 복구, 복구 직전 앱 실행 상태, 시작 시각 미확인, 아직 처리 중인 요청의 조기 복구 거부, 앱 정지 후 복구를 확인했습니다. 이 테스트는 실제 계정으로 새 복구 경로를 실행한 결과가 아닙니다. 실제 계정으로 확인한 API 동작은 위 표에만 기록합니다.

## 남은 실제 계정 비교

- 과거 날짜의 API 총시간·과목별 시간과 열품타 앱 화면 직접 비교. API 내부 합계는 일치했으나 앱 화면의 같은 날짜 값은 아직 직접 대조하지 않았습니다.

계정 검증을 할 때는 `scripts/probe-web-start-app-stop.mjs`를 로컬 터미널에서 실행할 수 있습니다. 실제 공부시간을 생성합니다. 중단되거나 결과가 불확실하면 앱에서 상태를 확인하고 타이머를 직접 정지해야 합니다.

과거 날짜 확인만 필요하면 `scripts/probe-history.mjs`를 실행합니다. 비밀번호는 숨겨서 입력하고 JWT는 메모리에서만 사용합니다. 이 도구는 타이머를 조작하지 않습니다.

가입 그룹과 멤버 상태는 `scripts/probe-groups.mjs`로 읽기 전용 확인을 합니다. 닉네임은 비교를 위해 로컬 터미널에만 표시하고 비식별 결과 파일에는 저장하지 않습니다.

2026-09-24 역방향 검사 1회는 `/user/sign-in-jwt`가 `s:false`를 반환해 로그인 단계에서 중단됐습니다. `/study/start`는 호출되지 않았으므로 이 검사로 시작된 타이머는 없습니다. 비밀번호와 서버 오류 코드는 기록하지 않았습니다.
